Regent Architecture v2

Revised after the landscape check. The proxy and the generic policy engine already exist as well-funded open source; Regent does not rebuild them. It is the vertical compliance product that sits on top of them: regulatory policy packs, approval workflows a compliance officer recognises, auditor-ready evidence, and a control plane across gateways.

What changed since v1. Two projects cover most of what v1 proposed to build: agentgateway (Linux Foundation, Rust, Apache-2.0, 4.6k stars) is the runtime proxy for MCP, A2A and LLM traffic with JWT/API-key auth, CEL authorization on tool name and arguments, external authz (Envoy ext_authz gRPC/HTTP), and OpenTelemetry. Microsoft Agent Governance Toolkit (Apr 2026, MIT, 6.1k stars, Python-first plus TS/.NET/Rust/Go) has YAML/OPA/Cedar policy, SPIFFE/DID identity, sandboxing, Merkle audit trails, require_approval gates, and mapping to OWASP Agentic Top 10, NIST AI RMF, EU AI Act and SOC 2. A long tail (custos, mcp-airlock, behavry-proxy, Provenrail, Clay Seal) does hash-chained ledgers and evidence bundles. Writing another proxy or another generic policy engine has zero chance. The name “agentgate” is taken at least six times.

1. What is still open

Everything above is built by engineers for engineers, mapped to generic frameworks, and stops at “we logged it and here is a table of controls.” Nothing found does the following, and these are the four things Regent builds:

Vertical regulatory packs

Policies written against the actual rules a firm is examined on: FINRA 3110 (supervision), 4511 (books and records), SEC 206(4)-7, Reg S-P, HIPAA §164.312, PCI DSS 4.0 §7–10. Not “NIST AI RMF Govern 1.1”.

Compliance-grade approval workflows

Four-eyes, delegation, time-boxed grants, attestation on approve, escalation, separation of duties. What a CCO already runs for humans, applied to agents.

Auditor-ready evidence

Per-period package: policies in force and their history, exceptions, approvals, denials, coverage gaps, all keyed to control IDs an examiner asks for. Generated, not assembled by hand.

Cross-gateway control plane

One policy source of truth pushed to agentgateway, AGT in-process, or a bare MCP proxy; fleet view; SSO/RBAC; alerts. Nobody spans runtimes.

2. The layer stack, with ownership

Same six layers as v1. What changed is who supplies each one. Blue is agentgateway, teal is the Microsoft toolkit, amber is Regent. Regent never sits inline on the data path in production — it is the policy decision service and the evidence system the runtime calls out to.

3. Where Regent plugs in

agentgateway exposes Envoy-style external authorization (gRPC by default, HTTP alternative) with method, path, headers and body available, and JWT claims passable as metadata. MCP tools/call is an HTTP POST whose body carries the tool name and arguments, so an ext_authz service sees everything it needs. Regent’s Policy Decision Service (PDS) answers allow / deny / hold-for-approval; on hold it returns 403 with a retry hint while the approval runs out-of-band, and the agent re-issues after approval with a grant token. Audit comes from agentgateway’s OTel exporter into Regent’s ingester, which hash-chains and maps it.

5. Worked case: RIA portfolio agent (through agentgateway)

Same firm as v1: 40-person RIA, agent portfolio-assistant with custodian, CRM, email and e-sign MCP servers, CCO answerable for SEC 206(4)-7, Reg S-P and FINRA-style books and records. agentgateway federates the four servers; Regent’s RIA pack is compiled to CEL for the cheap checks and the PDS handles anything needing approval or state.

# packs/ria/trading.yaml — readable by the CCO; compiled to CEL for agentgateway, Cedar for AGT
pack: ria/v1
rules:
  - id: RIA-TRD-001
    tool: custodian.place_trade
    allow_if: args.notional_usd <= 5000 and args.account in principal.assigned_accounts
    hold_if:  args.notional_usd > 5000
    approval:
      workflow: four_eyes
      approvers: role:supervising_principal
      attest: "I have reviewed this trade for suitability under the client's IPS."
      grant_ttl: 10m
    deny_if: args.security_type in [options, margin] and not principal.options_approved
    controls: [FINRA-3110(b), SEC-206(4)-7, FINRA-4511]
    examiner_asks: "How are agent-initiated trades supervised above your threshold?"

  - id: RIA-DAT-004
    tool: email.send
    deny_if: contains_pii(args.body, [ssn, account_number])
    no_override: true
    controls: [SEC-RegS-P-248.30, GLBA-501(b)]
    examiner_asks: "What prevents non-public personal information leaving via automated channels?"

6. Building it to encompass anything

The v1 hexagonal core survives, but the ports change: the runtime is now a port too. Regent’s core sees a normalised ToolCall and returns a Decision; a runtime adapter translates from whatever is enforcing (agentgateway ext_authz, AGT plugin, stdio shim, or a future gateway) and a compiler emits each runtime’s native policy dialect for the cheap rules.

# regent/core/ports.py
class Runtime(Protocol):                     # agentgateway_extauthz · agt_plugin · stdio_shim
    async def serve(self, decide: Callable[[ToolCall], Awaitable[Decision]]) -> None: ...
    def compile(self, pack: Pack) -> NativePolicy: ...          # CEL · Cedar · Rego

class AuditSource(Protocol):                 # otel_otlp · agt_merkle · jsonl
    async def events(self) -> AsyncIterator[AuditEvent]: ...

class Approver(Protocol):                    # slack · teams · email · webhook · cli
    async def ask(self, hold: Hold, workflow: Workflow) -> Approval | Timeout: ...

class Store(Protocol):                       # sqlite (dev) · postgres · s3_worm
    async def append(self, entry: ChainedEntry) -> None: ...
    async def grants(self) -> GrantIndex: ...

class Pack(Protocol):                        # ria · broker_dealer · hipaa_practice · pci_ops · dev_default
    rules: list[Rule]; controls: ControlMap; examiner_questions: dict[str, str]

# core loop
async def decide(call, packs, grants, approver, store):
    rule = packs.match(call)                            # deterministic, unit-tested
    if rule.denies(call):            return Decision.deny(rule)
    if rule.holds(call):
        if g := grants.valid_for(call): return Decision.allow(rule, grant=g)
        hold = await store.open_hold(call, rule)
        asyncio.create_task(run_workflow(hold, rule.approval, approver, store))
        return Decision.hold(hold.id)                   # gateway returns 403 + retry hint
    return Decision.allow(rule)

# evidence
async def ingest(source, packs, store):
    async for ev in source.events():
        entry = ChainedEntry.from_(redact(ev)).link(store.head())
        entry.controls = packs.controls_for(ev.rule_id)
        await store.append(entry)

8. What can kill it, updated

Microsoft extends AGT’s compliance mapping into vertical packs — they have the framework list already and a compliance business next door (Purview). Solo.io ships a commercial compliance tier on agentgateway. Behavry or a funded NHI vendor gets to the RIA vertical first. The MCP spec absorbs approvals natively. And still the most likely: the software is fine and nobody sells it to CCOs. The counters remain the same and narrower: be the pack everyone copies, get into agentgateway’s docs as the reference ext_authz, get one RIA compliance consultant as a co-founder or advisor within 60 days, and be in the FINRA/SEC comment process for agent supervision guidance before it lands.
